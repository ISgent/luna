# Luna 🌙

Discord-персонаж, который ощущается как живой постоянный собеседник: помнит людей и события,
формирует отношения, бывает в разном настроении, шутит, спорит, поддерживает, говорит голосом.

Это НЕ «AI-ассистент с памятью». Архитектура — в [ARCHITECTURE.md](./ARCHITECTURE.md).

## Быстрый старт

Нужен Node.js ≥ 22.5 (лучше 24.x). FFmpeg НЕ нужен.

```bash
npm install
copy .env.example .env      # и заполнить
npm run smoke               # живая проверка всех компонентов
npm run dev                 # запуск бота (dev-режим, авторестарт)
```

Прод-запуск:

```bash
npm run build && npm start
```

## Панель управления (без консоли)

Двойной клик по **`Luna.bat`** — в браузере откроется панель `http://localhost:8787`.
Всё управление оттуда:

- **▶ Запустить / ⏹ Остановить / 🔄 Перезапустить** бота;
- **автозапуск при включении ПК** — галочка «Запускать смотрителя при входе в Windows»
  (регистрация в папке Startup, без админских прав) и «Сразу запускать бота вместе со смотрителем»;
- **статус**: в сети / запускается / остановлен / краш-цикл, аптайм, число авто-перезапусков;
- **автовоскрешение при падении** бота (включено по умолчанию, можно выключить);
- **живой лог** и кнопка **🔨 Собрать** (`npm run build`);
- **настройки**: голос TTS, модели, уровень логов — сохраняются в `.env`, бот перезапускается сам.

Под капотом: `tools/supervisor.mjs` — фоновый смотритель (обычный Node-процесс без окна).
Панель доступна только с этого компьютера (127.0.0.1). Кнопка «✖ Закрыть всё» останавливает
бота и закрывает смотрителя. Файл лога: `data/logs/luna.log` (ротация на 5 МБ).

## Что положить в .env

Минимум для текстового режима:

```env
DISCORD_TOKEN=...        # токен бота из Discord Developer Portal
OWNER_ID=...             # ваш Discord ID — с ним Luna «давно знакома»
DASHSCOPE_API_KEY=...    # ключ DashScope (или LLM_API_KEY для другого провайдера)
```

Голосовой режим работает с тем же ключом DashScope: TTS `qwen3-tts-flash` (голос — `TTS_VOICE`,
например Cherry/Serena), STT `qwen3-asr-flash`. Провайдер/модель/голос меняются ONLY через env —
код трогать не нужно (подробности в ARCHITECTURE.md).

В Discord Developer Portal для бота нужны intents: **Message Content**, **Server Members** (не обязателен),
для голоса — обычное право Connect/Speak.

## Команды в Discord

| Команда | Что делает |
|---|---|
| `/memory list [count]` | показать, что Luna помнит о вас |
| `/memory delete <id>` | удалить конкретную запись |
| `/memory wipe` | стереть всю память о вас и обнулить отношения |
| `/memory on/off` | выключить/включить запись памяти о вас |
| `/luna mood` | текущее настроение Luna |
| `/luna stats` | статистика вашего общения |
| `/luna tts on/off` | озвучка ответов лично вам |
| `/luna voice on/off` | обработка вашего голоса лично вам |
| `/voice join` / `/voice leave` | позвать Luna в голосовой канал / вывести |
| `/luna telemetry` | последние замеры латентности (владелец) |
| `/luna reset <user-id>` | сбросить память и отношения о пользователе (владелец) |

Как разговаривать текстом: в личных сообщениях — всегда; на сервере — упомянуть `@Luna`
или ответить на её сообщение.

## Команды обычными словами (без слэшей)

Действия понимаются в человеческой формулировке — текстом или голосом:

- «@Luna **го в голос**» / «зайди ко мне в войс» / «подключись к моему каналу» — сразу зайдёт в ваш голосовой канал;
- «**выйди из канала**» / «покинь голос» — выйдет;
- «**замолчи**» / «хватит говорить» — остановит озвучку;
- «**выключи озвучку**» / «включи звук обратно» — настройка озвучки лично вам.

Работает двумя слоями: ходовые формулировки ловит локальный парсер (мгновенно,
без обращения к модели — Luna просто отреагирует в характере: «захожу!»), а любую
другую фразу Luna понимает сама и вызывает действие через tool calling
(`join_voice` / `leave_voice` / `stop_speaking` / `set_tts`). Оба слоя идемпотентны —
двойное срабатывание безопасно. Слэш-команды из таблицы выше тоже продолжают работать.

## Скрипты

```bash
npm test                   # все тесты (unit + интеграционные сценарии)
npm run typecheck          # строгая проверка типов
npm run smoke              # живая проверка: БД, LLM, стрим, embeddings, TTS→WAV, STT, e2e, Discord
npm run benchmark          # латентность горячего пути на живых провайдерах (p50/avg/max)
npm run benchmark -- --mock --rounds=10   # накладные расходы самой системы (без сети)
```

`smoke` сохраняет озвученную фразу в `data/smoke-tts.wav` — можно послушать голос.

## Как устроено (кратко)

- **Быстрый ответ**: сообщение → контекст из SQLite (~1мс) → поиск по памяти (один вызов
  эмбеддингов, при сбое — поиск по словам) → ОДИН стриминг-запрос к LLM → первое предложение
  сразу в канал. Вся аналитика (память, отношения, эмоции) — в фоне после ответа.
- **Память**: объективные факты отдельно от впечатлений Luna; дедупликация повторов;
  консолидация мелочи; эмоции событий не путаются с текущим настроением.
- **Отношения**: с каждым человеком свои, развиваются плавно; владелец — «старый знакомый» с порога.
- **Надёжность**: таймауты, ограниченные ретраи, circuit breaker на провайдера;
  упавший TTS/STT/память не роняют текстовый ответ.
- **Латентность измеряется**: каждый запрос пишет спаны в таблицу `telemetry` — видно,
  почему ответ занял именно столько.

## Структура

```
src/config      конфигурация из env (zod-валидация)
src/logging     логи (pino, секреты глушатся) и телеметрия латентности
src/utils       ретраи/брейкеры, очереди, текст, аудио/VAD
src/storage     SQLite + репозитории
src/ai          LLM/TTS/STT/embeddings — интерфейсы + адаптеры + моки
src/luna        личность, эмоции, отношения, память
src/core        контекст, промпт, менеджер разговора, шина событий
src/processing  фоновый конвейер и очереди ответов
src/bot         discord-клиент, команды, голос
scripts/        smoke-тест и бенчмарк
tests/          unit + интеграционные сценарии
tools/          панель управления: supervisor.mjs (фоновый смотритель + HTTP API), panel.html
Luna.bat        двойной клик — открыть панель (поднимет смотрителя, если нужен)
```

Секреты — только в `.env` (в git не попадает). Данные — в `data/luna.db` (тоже в .gitignore).
